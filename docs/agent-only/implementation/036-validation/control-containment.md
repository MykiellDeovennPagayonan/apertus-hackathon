# Scoped control containment and support context

The restored baseline run 2026-10-14T01-18-05-141Z-62350 had 40 render passes but crowded generated controls, a tree for slope, and a can for bridge.

This patch groups newly generated controls by their existing scope in a collapsed Additional controls disclosure. Existing authored controls remain in the main layout. The disclosure has its own bounded scrolling area; all widgets, command connections and values remain present. Learner arrangement preserves disclosures and derives their placement scope from their descendants. No controls are removed by this presentation change, and no scientific model or configuration is changed.

The existing supported/inputs inference response format, call count, candidate retrieval, budgets, configuration and assembly decisions are retained. Its context now supplies actual command fields, output meanings and units, rather than preset activity questions or teaching-observation summaries. Apertus still decides semantic support; application code adds no benchmark-specific routing or lexical eligibility rule.

The disclosure check covers all 40 recipes, comparing grouped and ungrouped nodes, resources and connections, validating documents, checking scope/placement, and checking collapsed native HTML. A mocked support check verifies the unchanged response contract and executable context; it is not live semantic evidence. Type checking covers affected callers. The full local Apertus/local Laya run and screenshot review provide live evidence separately.

The compact disclosure reserves 64 board units while closed, including when a taller control shares its row. Containers consisting entirely of controls retain their control placement role, keeping authored controls ahead of additional controls. Expanded content includes padding within its height limit. An unscored browser check verifies native mouse/keyboard expansion, bounded scrolling and field-value retention; it does not certify runtime command dispatch or semantic selection.

Responsive learner workspaces center short opening content horizontally and vertically between the measured floating header and composer, preserving zoom and canvas dimensions. Content taller than the available screen starts below the header. Authoring views and manually panned cameras keep their existing behavior. Focused camera checks cover short-content centering at different zoom levels and tall-content top alignment; the centered layout was reviewed in the five-case local run 2026-10-14T03-03-53-152Z-5573. Tall water/tree content still overlaps the composer, and the pendulum period label appears partly clipped.

Limitations: generated controls may still be duplicated or unnecessary internally, and requested capabilities absent from a model are not added. Required generated interactions remain accessible inside the disclosure. The support decision remains model-dependent and may reject suitable activities or accept unsuitable ones. A browser render pass is not a semantic quality score.
